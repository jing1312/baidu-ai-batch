# baidu-ai-batch · 百度网盘 AI 成果批量收割机

> 你的网盘里躺着几百节网课视频，每一节都自带 AI 生成好的课件、讲稿和笔记——但手动导出它们要点击上千次。
> 这个工具把「登录态」交给浏览器，用一行命令替你完成这 150 次机械劳动。

**实际战果**：作者用它处理了 4 门专业课共 153 节视频，自动导出 **146 份 AI 课件 PPT、122 份讲稿、55+ 份笔记**——而这些原本需要对着屏幕逐条点击 300+ 次。

---

## 为什么会有这个项目

百度网盘的「AI 视频」功能（AI 课件、AI 讲稿、AI 笔记）对每一节视频都是**服务端一次性生成**的：

- 生成结果只存在于网盘里，没有批量导出入口
- 想要 PPT？逐条点开视频 → 切「课件」标签 → 等加载 → 点导出
- 想要讲稿？再重复一遍 → 复制 → 粘贴到本地
- 153 节视频 = 453 次重复操作，且中途不能走神

更关键的是：**AI 生成是有额度的、功能是可能下线的**。辛辛苦苦生成的成果不落盘备份，就像没生成过。这个项目就是为「把网盘里的 AI 成果一次性搬到本地」而生。

## 它替你做什么

| 任务 | 输入 | 输出 |
|------|------|------|
| `export-ppt` | 视频清单 | 每节视频的 AI 课件 PPT，自动保存到网盘视频所在文件夹 |
| `extract-manuscript` | 视频清单 | 每节视频的 AI 讲稿，本地 TXT 存档 |
| `export-notes` | 视频清单 | 触发 AI 笔记生成 → 点击导出（PDF 存网盘）+ 本地 TXT 备份 |

全程无人值守：程序自己打开视频页、等 AI 加载、点按钮、收成果，你该干嘛干嘛。

## 设计巧思（为什么它稳定）

这个项目的每个细节都来自真实踩坑，不是玩具脚本：

**1. 复用登录态，零接口开发**
不逆向、不登录打码、不碰付费 API——直接把命令发给用户已登录的浏览器，网盘把 AI 能力白送的事，我们只负责收。门槛只有一个：浏览器开个调试端口。

**2. 新标签页隔离，不打扰你上网**
每个任务在 `Target.createTarget` 新建的隐身工作标签页里完成，做完即关。脚本跑批时你继续刷网盘、看文档，互不干扰——这是「能边跑边干别的」的底气。

**3. 找到真正的导出按钮**
网盘页面里其实有两个「导出 PPT」：AI 聊天窗口的快捷指令（会调用错误 API，100% 失败）和课件区右上角真实的导出图标（`.ai-course__export-container`）。早期版本被前者坑了两轮，最终定位到了真正生效的那个。

**4. 绕开 iframe 跨域限制**
笔记内容渲染在 `#noteIframe` 里，同源脚本读不到。解法很朴素：**把 iframe 的 URL 在新标签页打开**，让笔记编辑器自己变成顶层页面，DOM 随便读。

**5. 断点续传，失败不慌**
PPT 进度实时写入 `state.json`，中途断电、超时、CDP 断连，重跑只会处理没完成的；文稿/笔记按本地文件存在与否自动跳过，`--force` 可强制重跑。

**6. 识别「假成功」**
AI 生成失败时页面会留下 85~91 字的占位模板，看起来像是「导出成功」。脚本按内容字数阈值判定，占位结果不会写入成果，避免你拿一堆空壳文件去交作业。

**7. 为服务端限流让路**
早期并发 20 路狂点，PPT 失败率飙到 80%；调回串行 + 等待元素出现后，单节成功率接近 100%。批量工具的可靠性往往不是「跑得更快」，而是「跑得让平台安心」。

## 适用场景

- 🎓 **学生党**：一学期 4 门课 150 节网课，期末前把全部 AI 课件/讲稿/笔记一键归档，复习时本地全文搜索
- 👩‍🏫 **讲师/UP 主**：把网盘里的录课视频批量转成 PPT + 讲稿，做二次分发、字幕稿、讲义
- 📚 **知识管理**：让网盘 AI 把纪录片、播客、会议录像批量生成结构化笔记，沉淀为自己的知识库语料
- 🗄️ **成果备份**：AI 生成有额度限制、功能随时可能调整，把成果及时落盘到本地才真正属于你
- 🔁 **任何网盘视频**：不限于课程——只要是网盘 AI 功能支持的文件，改一行配置就能跑

## 快速开始

### 环境要求
- Node.js ≥ 18
- Edge / Chrome（以调试模式启动，并登录百度网盘）

### 1. 启动调试浏览器

```bash
msedge --remote-debugging-port=9222
# 或 chrome --remote-debugging-port=9222
```

> 调试端口浏览器与日常浏览器互相独立，需要在调试浏览器里重新登录一次网盘。之后可以一直挂着。

### 2. 安装与配置

```bash
npm install
cp config.example.json config.json   # Windows: copy config.example.json config.json
```

编辑 `config.json`，通常只需要改一处：

```jsonc
{
  "videoFolder": "/我的资源/课程视频/",  // ← 你的视频在网盘哪个目录
  "skipList": []                         // ← 想跳过的视频（如黑屏/损坏）
}
```

生成视频清单（自动调用网盘 API 列出目录）：

```bash
node bin/list-files.cjs
```

### 3. 开跑

```bash
node bin/export-ppt.cjs          # ① 批量导出 AI 课件 PPT
node bin/extract-manuscript.cjs  # ② 批量提取 AI 讲稿 → 本地 TXT
node bin/export-notes.cjs        # ③ 批量生成并导出 AI 笔记（--force 重跑）
```

三个任务独立，可以分开跑、随时中断、随时续跑。跑完 `output/` 里就是全部讲稿和笔记，PPT 在网盘视频目录里。

## 配置项一览

| 字段 | 说明 | 默认 |
|------|------|------|
| `host` / `port` | 浏览器调试地址 | `127.0.0.1:9222` |
| `panBase` | 网盘域名（自建网盘/其他区域可改） | `https://pan.baidu.com` |
| `videoFolder` | 网盘内视频目录，以 `/` 结尾 | `/我的资源/课程视频/` |
| `listFile` | 视频清单文件 | `video-list.txt` |
| `stateFile` | PPT 进度存档（断点续传） | `state.json` |
| `outputDir` | 讲稿/笔记本地输出目录 | `output/` |
| `skipList` | 跳过处理的视频名数组 | `[]` |
| `minContentLen` | 判定内容有效的字数阈值（识别「假成功」） | `100` |

> `config.json`、`state.json`、`output/` 已在 `.gitignore`，个人配置和成果不会污染仓库。

## 工作原理

```
node bin/*.cjs
   │  HTTP  ┌─────────────────────────┐
   ├──────► │ 浏览器 CDP 接口 :9222   │
   │        │  (msedge --remote-...)  │
   │  WS    └───────────┬─────────────┘
   └────────────────────┘
        打开新标签页 → 导航到视频页
        → 切「课件/文稿/笔记」标签 → 等 AI 加载
        → 点导出 / 抓 DOM → 收成果 → 关标签页
```

依赖仅 `ws` 一个包，无浏览器内核、无插件、无后台服务。

## 已知限制（诚实声明）

- 网盘 AI 成果是**服务端生成**的：若某视频的课件/讲稿/笔记持续为空或只有占位模板，通常是服务端生成失败，重跑无效，需在网页端手动重试该节
- 每次点击 PPT 导出都会在网盘生成带时间戳的新文件，重复运行会产生重复文件，需自行清理
- 串行执行是特性不是缺陷：并发调高会触发服务端限流，成功率骤降
